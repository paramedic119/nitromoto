## 0. レビュー反映サマリ（今回の主な変更）

- **ニトロを加速の主役**に。坂の加速は控えめにし、難所はニトロなしでは越えられない設定（「貯めて使う」駆け引きを守る）。
- **スコアを走行距離(m)メイン**に変更（時間は参考表示）。
- **360度ループは厳密な物理計算をやめ「判定ゲート＋演出」に割り切り**、実装は最後に回す。
- **着地マーカー・難所予告で「理不尽な死」を防ぐ**（予見可能性）。失速して止まる"緩慢な詰み"は即クラッシュにしてテンポを守る。
- **最小コアから段階的に作るマイルストーン（M0〜M7）**を追加。
- 技術: **固定タイムステップ＋弧長の区間判定**ですり抜け（トンネリング）を防止。**地上⇔空中の状態遷移**を明記。

## 1. コンセプト

一言で言うと **「ニトロを溜めて、ここぞで放って、走り抜けろ」**。

スマホ特化の横視点（サイドビュー）モトクロス・エンドレスラン。無限に自動生成される
コースを、ニトロ加速を駆使して可能な限り遠くまで走る。差別化の核は
**「ニトロ温存の駆け引き × 即死エンドレス」**（360度ループはあくまで見せ場であり、
ゲームの核ではない）。

- プラットフォーム: モバイルWebアプリ（スマホ最優先）
- 公開: GitHub にアップし、GitHub Pages で配信できる構成
- 操作: 画面タップ（1ボタン）のみ

## 2. ゲームルール

| 項目 | 内容 |
|------|------|
| 形式 | エンドレス型サバイバル（ゴールなし、無限生成） |
| 操作 | 画面をタップ（押している間）でニトロ噴射＝加速 |
| 失敗 | コースから落ちる／失速で止まる → 即クラッシュ → 記録 → タップで即リスタート |
| スコア | **走行距離(m)をメイン**。経過時間は参考表示 |
| 記録 | ベスト距離を localStorage に保存。ベスト地点にマーカー表示 |

## 3. 物理モデル（コースライン追従型）

バイクを「地面のライン上を進む点」として扱う軽量モデル。

### 3.0 計算の安定性（固定タイムステップ）

物理は**固定間隔（例: 1/120秒）のアキュムレータ方式**で計算し、描画だけ可変
フレームレートにする。高速時に地形やアイテムを飛び越える不具合（トンネリング）を
防ぐため、すべての通過判定（ニトロ取得・ループ頂点・セグメント境界）は「位置」では
なく **弧長 `s` がしきい値を跨いだか（区間跨ぎ判定）** で行う。

### 3.1 速度

道のりに沿った速度 `v` を持ち、毎フレーム次の力で増減する。

- **坂の重力（控えめ）**: 傾き角 θ に対し `a = -g·sin(θ)`。ただし係数を小さく抑え、
  **坂の加減速だけでは難所（ループ・大ギャップ）を越える速度には届かない**ようにする。
  坂は「ニトロを節約できるボーナス／ロスする区間」という補助的役割。
- **ニトロ（主役）**: タップ中は強めの推進加速度 `+N` を加える（ゲージ消費）。
  難所突破の主手段。
- **抵抗**: 速度に比例する軽い減速 `-k·v`。
- **失速の即クラッシュ**: 速度が下限 `v_min` を下回ったら即クラッシュ。
  上り坂で止まりかけて"ジワジワ詰む"無力な時間をなくし、即リスタートのテンポを守る。

### 3.2 地上⇔空中の状態遷移（GROUNDED ⇄ AIRBORNE）

物理の核心。バイクは常に `airborne`（地上か空中か）の状態を持つ。

- **GROUNDED**: 弧長 `s` で地形ラインに追従。座標は `s` から算出。
- **AIRBORNE**: `(x, y, vx, vy)` で放物運動（重力で落下）。
- **離陸**: ジャンプ台の終端、または地形が急に下がってラインに追従しきれなくなった
  とき AIRBORNE へ遷移。離陸時、接線方向のスカラー速度 `v` を `(vx, vy)` に分解。
- **着地**: 放物線と地形ライン（折れ線）の交差を、1フレームを細かく刻んだ
  サブステップ走査で検出（飛び越し取りこぼし防止）。着地点で `(vx, vy)` を
  地形の接線方向へ射影してスカラー `v` に戻し GROUNDED へ。
- **着地角度**: 進行方向と着地地形の傾き差が閾値を超えたらクラッシュ。
  → 飛ぶ前に **着地点マーカー** を表示して事前に分かるようにする（3.5）。

### 3.3 ジャンプ / ギャップ

- コースの切れ目（ギャップ）やジャンプ台の終端でバイクが離陸（3.2）。
- 速度不足でギャップに届かず谷へ落ちるとクラッシュ。

### 3.4 360度ループ（判定ゲート＋演出に割り切る）

厳密な連続物理シミュレーションはしない（調整不能になり「ほぼ常に成功／失敗」の
両極端になるため）。代わりにゲーム的な近似で処理する。

- ループ進入時に **必要速度 `v_required = √(g·r) × 係数` を1回だけ判定**。
- **成功**: バイクの姿勢を 0→360度 に補間して回す演出（位置はループ曲線に拘束）。
- **失敗**: 頂点付近で接線方向へ離脱 → 放物落下 → クラッシュ。
- ループ手前には十分なニトロ獲得導線を**保証**して配置（4章）。
- 難易度は係数1つで調整できるようにする。

### 3.5 クラッシュ条件（まとめ）

- ループ判定の失敗 / ギャップを越えられず落下 / 着地角度の過大 / 速度下限割れ。
- いずれも「コースより下（画面下端より下）に落ちた」または「失速停止」で確定。

## 4. ニトロシステム（ゲームの主役）

- ゲージ `0 〜 MAX`。コース上の**ニトロカプセル**を通過で取得しゲージ増加。
- タップ中、毎フレーム消費しながら強く推進。空だと噴射不可。
- **配置の保証（運ゲー防止）**: 各難所（ループ・大ギャップ）の手前には、
  クリアに足りるだけのニトロを獲得できる導線を**必ず**置く。
  ランダム性は「余剰分の配置」や「取りに行くとリスクがある位置」で出す。
- 駆け引き: 難所の手前で使うために温存する。これがゲームの中心。

## 5. コース自動生成（契約ベース）

右方向へセグメント単位で無限生成する。

- **生成は契約ベース**: 各セグメント生成関数を
  `generate(startHeight, startSlope) → { points[], endHeight, endSlope }` の形に統一し、
  接続点で**高さと傾きの両方を連続（C1連続）**させることを生成側の不変条件にする
  （接続点での不自然な跳ね／詰まりを防ぐ）。
- **セグメント種別**: 平坦 / 起伏（sin波） / 上り坂 / 下り坂 / ジャンプ台＋ギャップ /
  360度ループ。
- **難易度カーブ**: 「進行距離 → セグメント種別の出現重み」のテーブル1枚に集約し、
  進むほど難所の頻度・サイズを徐々に増やす。
- ニトロカプセルは難所とセットで配置（4章の保証）。
- 画面外に出た過去セグメントは破棄してメモリを節約。

## 6. 描画（HTML5 Canvas 2D）

- カメラがバイクを追従し、右へスクロール。
- バイク: 車体＋2輪の簡易図形。地形の傾きに合わせて回転し、ループでは360度回る。
- 地形: ラインの下を塗りつぶし。
- **予見可能性（理不尽死の防止）**:
  - **着地点マーカー**: ジャンプ中、着地予測地点を表示。
  - **難所予告**: これから来るループ・大ギャップを画面端アイコンやカメラ先読みで予兆表示。
- **ベスト距離マーカー**: 自己ベスト地点に旗／ゴーストを表示し「あと少し」を演出。
- UI: ニトロゲージ、走行距離、経過時間、ベスト距離。
- **成功体験を厚くする演出**: ループ通過のスロー＋フラッシュ、着地成功の砂埃＋軽い
  画面シェイク、ニトロ満タンのゲージ発光、ニトロ噴射の炎パーティクル。
- **パフォーマンス**: `devicePixelRatio` は上限クランプ（例: 最大2.0）。描画は画面内に
  見えている範囲のみ。背景パララックスは層数を絞る。

## 7. 技術構成

- **バニラ JavaScript + HTML5 Canvas**（外部ライブラリ・ビルド工程なし）。
- ES Modules で責務ごとに分割。
- `requestAnimationFrame`（描画は可変、物理は固定ステップ＝3.0）。
- タッチ／マウス両対応。

### ファイル構成（案）

```
index.html          # エントリ、Canvas、UI要素
css/style.css       # スタイル
js/
  main.js           # 初期化・ゲームループ（固定ステップのアキュムレータ）
  game.js           # 状態管理（プレイ中 / クラッシュ / リスタート、距離スコア）
  track.js          # コース自動生成（契約ベース、ニトロ配置保証）
  bike.js           # バイクの物理・状態（GROUNDED⇄AIRBORNE 状態機械）
  renderer.js       # 描画（マーカー・予告・エフェクト含む）
  input.js          # タッチ／マウス入力
  storage.js        # ベスト距離保存
```

（物理計算はまず `bike.js` 内に置き、複雑化したら `physics.js` に切り出す。
`bike.js` の冒頭に GROUNDED⇄AIRBORNE の状態遷移を擬似コードで明記してから実装する。）

## 10. 実装マイルストーン（最小コアから段階的に）

各段階で必ずスマホ実機で「触って楽しいか」を確認してから次へ進む。常に動くものを保つ。

- **M0**: 画面で四角が右に動く＋タップで速くなる（ゲームループとタッチ動作の確認だけ）。
- **M1 ★MVP**: 直線＋坂の地形ライン上を走り、坂で加減速＋タップで加速。
  → **最初の手応え検証**。ニトロはこの段階では仮（無限）でよい。
- **M2**: 落下／失速で即終了＋距離スコア＋タップでリスタート（ゲームとして成立）。
- **M3**: 無限生成（平坦・起伏・坂のみ）＋ベスト距離保存（エンドレス成立）。
- **M4**: ジャンプ／ギャップ（離陸・着地・着地点マーカー）。
- **M5**: 360度ループ（判定ゲート＋演出）。※M1〜M4が完成してから最後に挑む。
- **M6**: ニトロゲージ＆カプセル＆配置保証（温存の駆け引きを最後に重ねる）。
- **M7以降**: 背景パララックス・パーティクル・難易度調整・サウンド。

## 11. 最優先で潰すリスク（プロトタイプで先に検証）

1. **M1で「坂＋タップ加速の走行感」が指に気持ちよく馴染むか。** これが企画全体の生死を
   決める。退屈なら機能を盛っても救えない。
2. 次に **「ニトロを温存→難所で放って突破」の駆け引きが、現実的なパラメータ
   （`g, r, N, k`）で成立するか**（M6の前に小さく試す）。成立する調整幅がなければ
   コアが崩れる。
